# HSF 均质表自动填写工具

> 把「材料成分表」`.xls` 一键转成成套的「均质创建导入表」——自动掏出单元格里内嵌的
> 检测报告与 MSDS，解析编号 / 机构 / 日期 / 测试结果，填好模板，产出可直接导入的 `.xlsx`。

## 它解决什么问题

源表里每个材料都内嵌着若干份检测报告（HSF / SGS / ROHS）与 MSDS，全部以 OLE 对象的形式
塞在单元格里，肉眼看不见、导出靠手点。

手工流程是：逐份双击打开报告 → 抄报告编号 → 抄出具日期 → 逐项抄 29 个测试结果
（Pb / Cd / Hg / Cr6+ / PBBs / 邻苯 / 卤素…）→ 再算成分含量占比 → 填进导入模板。
一份材料十几分钟，几十份就是一下午，还容易抄错行。

这个工具把整条链路自动化了。

## 主要能力

| 能力 | 说明 |
|---|---|
| **直接掏内嵌 PDF** | 不依赖「另存为」或手工导出。`.xls` 本质是 OLE2 复合文档，报告以 OLE 对象存放在 `MBD<8位hex>` storage 的 `\x01Ole10Native` 流中，可直接取字节 |
| **三路 PDF 解析** | 版面 token 归列 / 列区间切片 / 普通模式行首标签，覆盖 SGS、华测、美信、HCT、TÜV、Intertek、必维等主流版式 |
| **扫描件 OCR 兜底** | 纯图片型 PDF 自动光栅化 → OCR → 按识别框坐标重建文本行 → 复用同一套解析逻辑 |
| **自动扩充模板行** | 模板仅预留 6 行成分 / 4 行报告，超出时自动插行**并搬运合并区** |
| **成分含量归一化** | 按重量占比折算到合计 100%，最大余数法保证加总精确、保留 2 位小数 |
| **必填项兜底** | Pb / Cd / Hg / Cr6+ 抽不到时按领域规则补 `ND`，绝不留空 |
| **可追溯** | 每个材料带独立告警列表，汇总表里标红，一眼看出哪几份需要人工复核 |
| **两种入口** | 拖拽式 GUI（双击即用）+ 命令行（便于批处理与自测） |
| **幂等** | 同一输出目录反复重跑结果稳定，不会累积出 `-1` / `-2` 副本 |

## 快速开始

### 1. 用打包好的 exe

从 Releases 下载 `HSF均质表自动填写工具_精简版.exe`，双击运行，把源表与模板拖进窗口即可。

也支持命令行批处理：

```bat
HSF均质表自动填写工具_精简版.exe --cli 源表.xls 模板.xlsx 输出目录
```

### 2. 从源码运行

```bash
pip install -r requirements.txt

python run_gui.py                                   # 图形界面
python run_cli.py 源表.xls 模板.xlsx 输出目录        # 命令行
```

源文件名里若识别不出芯片编号（形如 `RR12345`），命令行需显式指定，否则中止：

```bash
python run_cli.py 源表.xls 模板.xlsx 输出目录 --prefix RR12345
```

### 3. 自行打包

```bash
pip install pyinstaller

pyinstaller --noconfirm "HSF均质表自动填写工具.spec"        # 完整版（含 OCR）
pyinstaller --noconfirm "HSF均质表自动填写工具_精简版.spec"  # 精简版
```

打包环境用 **Python 3.12**：`--windowed` 单文件模式依赖 `tkinterdnd2`，部分精简发行版
的 3.13 环境不自带 tkinter。

## 输出产物

每次运行在指定输出目录里平铺产出：

```
{编号}-{材料名}.xlsx          每个 K 列合并格一份，填好的导入模板
HSF_{编号}-{材料名}.pdf        该格内所有检测报告合并成一份
MSDS_{编号}-{材料名}.pdf       与 HSF 严格一一对应
processing_log.txt            处理日志
_汇总报告.xlsx                 汇总表（告警行标红）
```

材料名取 D 列并剔除括号内容（`Die1(EMMJR68)` → `Die1`）；重名自动追加 `-1` / `-2`。

## 工作原理

```
材料成分表.xls（OLE2 复合文档）
  │
  ├─ xlrd 读表格 ─────────────► K 列每个合并格 = 一个材料块
  │                              （同时读 F/G/H 列：成分名 / CAS No. / 重量）
  │
  └─ olefile 遍历 MBD* storage
       └─ \x01Ole10Native ────► 内嵌 PDF 字节
                                   │
                         ┌─────────┴──────────┐
                         ▼                    ▼
                  pdf_parse 三路解析     ocr.py 扫描件兜底
                  ├ 版面 token 归列       光栅化 → OCR
                  ├ 列区间切片            → 识别框按 y 聚行
                  └ 普通模式行首标签      → 喂回同一套解析
                         │
                         ▼
            报告编号 / 机构 / 日期 / 29 项测试结果
                         │
                         ▼
            xlsx_build 填模板（自动插行 + 搬运合并区）
                         │
                         ▼
   {编号}-{材料名}.xlsx + HSF_*.pdf + MSDS_*.pdf + _汇总报告.xlsx
```

## 模块结构

| 模块 | 职责 |
|---|---|
| `src/hsf/config.py` | 列位、模板结构、测试项、机构规则、领域分组——所有业务常量集中于此 |
| `src/hsf/ole_extract.py` | 解析 OLE2 复合文档，抽取内嵌对象并还原文件名 |
| `src/hsf/xls_source.py` | 读源表、识别数据区与合并格、成分合并、含量归一化 |
| `src/hsf/pdf_parse.py` | PDF 三路解析，抓编号 / 机构 / 日期 / 测试结果；结果合并取最不利值 |
| `src/hsf/ocr.py` | 扫描件 OCR 兜底（可选依赖，缺失时降级） |
| `src/hsf/pdfout.py` | 多份 PDF 合并与规范命名另存 |
| `src/hsf/xlsx_build.py` | 按模板结构生成 xlsx，自动插行并搬运合并区 |
| `src/hsf/pipeline.py` | 主流程编排、告警收集、汇总报告 |
| `src/hsf/gui.py` | Tk 图形界面（后台线程 + `queue` + `after` 泵） |
| `src/hsf/util.py` | 文本清洗、CAS 清洗、日期解析、编号提取 |

## 填写规则

| 项目 | 取值 |
|---|---|
| 均质名称 | `{芯片编号}-{D列材料名}`（剔除括号内容） |
| 供应商 / 类别 / 型号 | `SAC` / `Metal` / `TBD` |
| 环保等级 / 颜色 | `Ⅰ级(无卤欧盟环保)` / `黑色` |
| 成分含量 | 按重量归一化到合计 100%，2 位小数 |
| 保密成分 | 「是否保密」填 `是`，CAS No. 填 `00-00-00` |
| CAS No. | 只保留数字与 `-`，其余字符一律剔除 |
| 报告编号缺失 | 填 `TBD00000000` |
| 日期缺失 | 同一单元格内「由一推多」；全缺则留空并在汇总表标红 |
| 必填项 | Pb / Cd / Hg / Cr6+ 不允许 `NA`，缺失按领域规则补 `ND` |

**领域分组规则**：`F/Cl/Br`、`PBBs+邻苯 6 项`、`DINP/DnHP/DIDP/DNOP`、`PFOA/PFOS`
各自为一组，组内只要有一项测出结果，其余仍为 `NA` 的项判定为抽取遗漏并补 `ND`。

> 模板允许 `NA`（含义为「未测试此项」），`NA` 的禁令**只约束 Pb / Cd / Hg / Cr6+** 四个必填项。

## 两个版本怎么选

| | 完整版 | 精简版 |
|---|---|---|
| 体积 | 约 111 MB | 约 35 MB |
| 扫描件 OCR | ✅ | ❌ |
| 适用 | 报告里混有扫描件 | 报告都是文本型 PDF |

精简版不含 `rapidocr-onnxruntime` + `pypdfium2`，体积小、启动快。

**降级范围比直觉更广**：OCR 的触发条件是「常规解析没抓到编号或测试结果」，
所以不只是扫描件会退化，**有文本层但版面解析失败的报告同样依赖 OCR 兜底**。
退化表现为编号填 `TBD00000000`、未测项填 `NA`（必填四项仍补 `ND`，不会出现 `NA`）。

降级**不静默**：OCR 不可用时启动会打 WARN，汇总表里也会逐份标注「本需 OCR 才能识别」。
看到这些告警就换完整版重跑。

## 值得记录的坑

这些都是实际调试中踩出来的，记在这里免得再犯：

1. **`insert_rows()` 不搬合并区**
   `openpyxl` 插行后合并单元格区域停留在原位，表格会错位。必须手动重建
   `MultiCellRange`（且**不能**先 `unmerge_cells()`）。

2. **`PdfReader` 必须保活到 `write()` 之后**
   `add_page()` 只把页对象引用挂到 writer 上，底层数据仍归 reader 所有。reader 一旦被 GC，
   页就变成空壳，写出一个没有内容的 PDF——不报错、不告警，直到打开才发现是空的。

3. **OCR 触发条件不能用「文本密度」**
   实测扫描件 532 字符/页、正常报告 854 字符/页，阈值根本区分不开，会把好 PDF 也送去 OCR。
   改为「常规解析没抓到编号或结果才启用」。

4. **可选依赖缺失会导致整块数据静默丢失**
   没打包 `cryptography` 时，遇到 AES 加密的报告会抛 `DependencyError`，异常一路冒泡，
   整个材料的 xlsx 都不生成——日志里只有一串堆栈，看不出少了哪一份。

5. **「文件已存在就避让」会污染重跑**
   PDF 另存时用 `while os.path.exists()` 避让，而 xlsx 是覆盖写，重跑到同一目录时
   PDF 会翻倍、后缀累积成 `-1-1`。避让范围应限于**本次运行内**已用过的名字。

6. **校验脚本的定位锚点不能用子串匹配**
   模板里成分表与报告表的 A 列都是 `*序号`，只有 B 列不同。用 `in` 匹配会先命中第 1 行的
   整段说明文字，导致后续逐格比对全部错位——**后果不是报错，而是报告「0 差异、全部通过」**。

7. **负向测试要注入到「校验真正覆盖的位置」**
   校验项按设计跳过保密行，若把缺陷注入到保密行上，测试会假通过。

8. **写死期望值的测试会掩盖真问题**
   断言写成 `n_msds == 12` 后，规则一改就同时报假失败**并遮蔽**了「PDF 翻倍成 48 份」的真 bug。
   改成关系断言 `n_msds == n_hsf` 才暴露出来。

9. **双 CLI 入口必然走偏**
   GUI 里内嵌一份 CLI 实现、`run_cli.py` 里又一份，加参数只改了一处，exe 走的还是旧的那份，
   参数静默失效。入口只允许存在一份实现。

10. **PyInstaller 重打包不要用 `rm` 清 `build/`**
    增量构建与安全删除策略冲突。把 `build/` 和旧 exe 改名让位，再 `--noconfirm` 全新构建即可。

## 依赖

```
# 运行必需
openpyxl>=3.1
xlrd>=2.0.1
pypdf>=4.0
olefile>=0.47
cryptography>=3.1        # pypdf 解密 AES 加密的 PDF，缺失会抛 DependencyError

# GUI 拖拽（可选，缺失时自动降级为按钮选择）
tkinterdnd2>=0.3

# 扫描件 OCR 兜底（可选，缺失时降级为 TBD00000000）
rapidocr-onnxruntime>=1.2
pypdfium2>=4.0
```
